# 07 — UI

## 1. Thành phần

| Công nghệ | Vai trò |
|---|---|
| React Flow | canvas, node/edge rendering, zoom/pan, selection, drag, minimap, controls |
| ELK.js | auto layout **phân cấp** (ELK hỗ trợ nested graph natively — cần cho loop/try/parallel subgraph): node lá được đo kích thước trước (render-measure theo content/mode), ELK tính vị trí con tương đối cha + size cha từ con; không hiểu semantics; chạy async |
| Monaco | code view, custom-code editor, diff view, developer mode |
| shadcn/ui | inspector forms, palette, dialogs |

Layout không bao giờ thay đổi semantic graph.

## 4. Progressive disclosure

| Cấp | Thấy gì |
|---|---|
| **Beginner** | chuỗi node có label + icon: `Get PRs → Check Auth → Send Slack`; edit qua form đơn giản |
| **Power user** | inspector đầy đủ: fields, expressions `{{ }}`, condition, loop config |
| **Developer** | Monaco full source, custom-code editor, diff view |

Cùng một graph, ba mức nhìn — không phải ba representation.

## 5. Editing UX

User có thể ([06-patch-engine.md](06-patch-engine.md) §2): edit editable fields, expressions, conditions, loop config; thêm node từ palette (tool hoặc library function — patcher tự chèn import khi cần); xóa node; đổi tool tương thích; mở custom code trong Monaco.

Với function library ([05-registry.md](05-registry.md) §4), UI hỗ trợ thêm:

- **tạo function mới**: mở Monaco, viết function + khai báo input/output, lưu vào library → xuất hiện ngay trong palette;
- **promote**: chuột phải local function / custom code node → "Save to library";
- **edit library function**: từ node bất kỳ đang dùng nó → "Edit Code" → sửa source; nếu đổi signature, flow đang mở hiện diagnostic ngay, các flow khác hiện khi được load lại (phạm vi thực tế — [05-registry.md](05-registry.md) §4).

Quy tắc UX bắt buộc:

- operation không được hỗ trợ → UI nói rõ ngay ("Chưa hỗ trợ di chuyển node giữa các nhánh — dùng code view"), không fail âm thầm, không làm gần đúng;
- node `code`/`unknown` hiển thị khác biệt rõ ràng (viền/style riêng) để user biết vùng đó chỉ edit được bằng code;
- diagnostics hiển thị trên node liên quan (badge) + panel tổng;
- mọi edit cho preview diff được (optional) trước khi apply.

## 6. Ví dụ end-to-end

Code (ví dụ chuẩn của specs — [01-flow-contract.md](01-flow-contract.md) §1):

```ts
import type { Tools } from "../generated/tools";
import { isAuthChange } from "@flows/lib";

export default async function flow(input: { repository: string }, tools: Tools) {
  const prs = await tools.github.getNewPRs({ repo: input.repository });
  for (const pr of prs) {
    const files = await tools.github.getFiles({ pr });
    if (files.some(isAuthChange)) {
      await tools.slack.send({
        channel: "#security",
        message: `Security PR: ${pr.title}`
      });
    }
  }
}
```

Projection — **đây là graph kỳ vọng chuẩn** mà acceptance test ([08-mvp.md](08-mvp.md) §4) đối chiếu. Danh sách node đầy đủ: `trigger`, `tool`(getNewPRs), `loop`, `tool`(getFiles), `condition`, `tool`(slack.send), `output`(synthetic — flow không có return tường minh):

```text
┌─────────────┐
│ ⚡ Trigger   │
└──────┬──────┘
       │ data: input.repository ─────→ Get New PRs
       ▼
┌─────────────┐
│ Get New PRs │
└──────┬──────┘
       │ data: prs
       ▼
┌───────────────────────────────────────────┐
│ For Each pr in prs                        │
│   (data: pr → Get PR Files, Slack Send)   │
│  ┌──────────────┐                         │
│  │ Get PR Files │                         │
│  └──────┬───────┘                         │
│         │ data: files                     │
│         ▼                                 │
│  ┌─────────────────────┐                  │
│  │ ◇ Is Auth Change?   │  ← condition node,
│  └──────┬───────┬──────┘    label từ registry (04 §2.2b),
│    true │       │ false     expression: files.some(isAuthChange)
│         ▼       │                         │
│  ┌────────────┐ │                         │
│  │ 💬 Slack   │ │                         │
│  │  #security │ │                         │
│  └──────┬─────┘ │                         │
│         └───────┴──→ (kết thúc iteration —│
│                       KHÔNG có merge node:│
│                       nhánh ở cuối block, │
│                       04 §2.4)            │
└──────────────────┬────────────────────────┘
                   ▼
            ┌─────────────┐
            │ ⏹ Output    │  synthetic — 04 §2.10
            └─────────────┘
```

Chi tiết đối chiếu: `isAuthChange` không phải node riêng (callback trong condition expression — 04 §2.2b); không có merge node trong loop vì hai nhánh của condition kết thúc block (04 §2.4); data edges gồm `input.repository` (trigger→getNewPRs), `prs` (getNewPRs→loop), `pr` (loop→getFiles và loop→slack.send, vì `pr.title` trong message), `files` (getFiles→condition).

User đổi channel `#security` → `#security-team` trong inspector → patch đúng một dòng ([06-patch-engine.md](06-patch-engine.md) §4) → graph re-render, mọi thứ khác giữ nguyên.

## 7. Performance targets

Với flow file thông thường (vài trăm dòng):

- initial analysis: **< 500 ms** — đạt được vì dựng graph chỉ cần **parse + scope analysis** (tool resolution là binding-rooted, [04-analyzer.md](04-analyzer.md) §1.2), KHÔNG cần full type check;
- analyze sau edit: **< 100 ms** — warm reuse: giữ parse tree/Project sống, re-parse file rồi re-analyze;
- **type-check enrichment** (type cho ports, validate) là tầng tách rời, chạy async ở Node/CI hoặc web worker — đến sau, không block việc dựng và hiển thị graph; browser không type-check được thì graph vẫn đầy đủ, chỉ thiếu type chi tiết trên port;
- UI update incremental qua `GraphChange[]` — "node không đổi không re-render" áp dụng cho **React component render** (memo theo node data); còn **vị trí** thì một thay đổi cấu trúc có thể làm ELK dịch nhiều node — chấp nhận, vì dịch chuyển vị trí không re-render nội dung node;
- layout chạy async, không block interaction.

Engineering targets, không phải semantic guarantees.
